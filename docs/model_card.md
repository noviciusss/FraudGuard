# FraudGuard Model Card

## Model Overview
- **Model Type**: Supervised Binary Classification Pipeline
- **Algorithms Evaluated**:
  - Baseline: `LogisticRegression(class_weight='balanced', solver='lbfgs')`
  - Production Champion: `XGBClassifier(n_estimators=150, max_depth=5, learning_rate=0.08)`
- **Input Features**: Allowlisted subset:
  - `type`: Categorical (`CASH_IN`, `CASH_OUT`, `DEBIT`, `PAYMENT`, `TRANSFER`) encoded via `OneHotEncoder(handle_unknown='ignore')`
  - `amount`: Transaction amount
  - `log1p_amount`: Derived `log(1 + amount)`
  - `sin_hour`, `cos_hour`: Cyclic 24-hour hour encoding derived from simulation step
- **Forbidden Features (Excluded by Design)**:
  - `oldbalanceOrg`, `newbalanceOrig`, `oldbalanceDest`, `newbalanceDest` (Warned against by PaySim creators due to cancellation artifacts)
  - `isFlaggedFraud` (Simulator business heuristic rule)
  - `nameOrig`, `nameDest` (Account identifiers)
  - `isFraud` (Supervised target)

## Threshold Policy & Calibration
- Fraud scores generated by weighted classifiers represent uncalibrated risk rankings rather than true posterior probabilities. The API outputs `fraud_score`, not a guaranteed probability.
- Decision threshold is selected on the **tuning partition only** to maximize recall subject to an operational False Positive Rate budget:
  $$\text{FPR} \le 0.01 \quad (1\% \text{ false-positive budget})$$

## Baseline vs Champion Comparison
Evaluated on disjoint temporal step partitions:

| Partition | Step Range | Metric | Baseline (Logistic) | Champion (XGBoost) |
|---|---|---|---|---|
| Development Tune | 73..90 | Average Precision (AP) | 0.215 | 0.161 |
| Development Tune | 73..90 | Recall @ FPR <= 1% | 45.9% | 37.8% |
| Final Audit | 109..120 | Recall @ Fixed Threshold | 40.0% | 28.0% |
| Final Audit | 109..120 | False Positive Rate | 0.98% | 1.18% |

*(Note: In conservative feature spaces without leaking balance columns, simple linear models can capture large transfer signals effectively; the evaluation suite audits both without bias).*
